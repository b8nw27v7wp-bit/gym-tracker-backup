# 内容数据规范（Content Guidelines）

版本：v2.21.0 | 更新：2026-08-13

> 本文件定义动作库与知识库的内容结构与写作标准，保证数据质量与可扩展性。扩充内容前必读。

## 1. 动作库规范

### 1.1 文件组织

```
data/exercises/
├── chest.js      胸（22 动作）
├── back.js       背（23 动作）
├── legs.js       腿（22 动作）
├── glutes.js     臀（15 动作）
├── shoulders.js  肩（19 动作）
├── arms.js       手臂（22 动作）
├── core.js       核心（18 动作）
（小腿已并入 legs.js，v2.26.7）
├── cardio.js     有氧（13 动作）
├── swimming.js   游泳（7 动作）
└── index.js      合并 + 部位知识 + 查询/搜索
```

### 1.2 字段字典

| 字段 | 必填 | 取值 | 写作要求 |
|-----|-----|------|---------|
| id | ✅ | 小写连字符 | 全局唯一，语义化（如 lat-pulldown），一旦发布不轻易改名 |
| name | ✅ | 中文名 | 使用健身圈通用叫法，同名动作加修饰词（上斜/窄距/坐姿） |
| muscle | ✅ | 9 个部位 key | 见 1.3 |
| type | ✅ | compound / isolate | 复合=多关节，孤立=单关节 |
| mechanic | ✅ | push/pull/squat/hinge/lunge/carry/core/other | 力学模式，未来可用于计划编排 |
| equipment | ✅ | barbell/dumbbell/machine/cable/bodyweight/kettlebell/band/plate/other | 器材枚举 |
| difficulty | ✅ | 1 / 2 / 3 | 1 入门（新手安全可做）2 进阶 3 高级（需要基础/协调性） |
| target | ✅ | 数组 ≥1 | 目标肌群，用标准解剖名（胸大肌/肱三头肌） |
| secondary | 可选 | 数组 | 辅助肌群，可为空数组 |
| steps | ✅ | 数组 ≥2，建议 3-4 条 | 按执行顺序，每条 1 个要点，动作名词+关键细节 |
| errors | ✅ | 数组 ≥2 | 每个错误 = 现象 + 后果/纠正方向 |
| rest | ✅ | 字符串 | "60-90 秒" 格式，按动作强度给区间 |
| tip | ✅ | 1 句 | 该动作最核心的"心法"，口语化、可记忆 |

### 1.3 部位枚举（10 个）

`chest` 胸 / `back` 背 / `legs` 腿 / `glutes` 臀 / `shoulder` 肩 / `arms` 手臂 / `core` 核心 / `cardio` 有氧 / `swimming` 游泳

> 注意：肩部位 key 是单数 `shoulder`（历史遗留），新增部位不要仿照，用复数形式。

### 1.4 动作写作质量红线

- 步骤必须可执行：别人照做能完成动作，禁止"注意发力"这类空话
- 错误必须具体：`手肘过度外展呈 90°，增加肩关节压力` 优于 `姿势不对`
- 技术准确性：肌群归属（如面拉 → 三角肌后束，不是斜方肌主练）、休息区间（复合长孤立短）不得出错
- 新手友好：每个动作至少让新手知道"做不到怎么办"（如引体 → 高位下拉替代）在 tip 或错误中体现

### 1.5 部位知识（index.js MUSCLES）

每部位 5 个字段：`key` 部位 key / `name` 中文 / `icon` emoji / `freq` 建议频率 / `desc` 一句描述 / `tips` ≥3 条训练要点 / `recommended` 3-5 个推荐动作 id（必须是该部位已存在的动作）。

## 2. 知识库规范

### 2.1 文件组织

```
data/knowledge/
├── principles.js   训练原理（6 篇）
├── plans.js        分化计划（4 篇）
├── lifestyle.js    营养/恢复/术语（9 篇）
├── advanced.js     进阶训练/补剂/动作详解（11 篇）
└── index.js        合并 + 分类定义
```

### 2.2 字段字典

| 字段 | 必填 | 写作要求 |
|-----|-----|---------|
| id | ✅ | 全局唯一，连字符 |
| title | ✅ | ≤ 20 字，信息明确（"渐进超负荷：增肌的第一原理"） |
| category | ✅ | 见 2.3 分类枚举 |
| summary | ✅ | ≤ 40 字一句话摘要，用于列表展示 |
| sections | ✅ ≥2 | 3-5 节为佳，见 2.4 |

### 2.3 分类枚举

`principles` 训练原理 / `plans` 分化计划 / `nutrition` 营养饮食 / `recovery` 恢复睡眠 / `glossary` 术语表

### 2.4 章节结构

```js
{ h: '小节标题', type: 'para', content: '段落文本' }        // 叙述型
{ h: '小节标题', type: 'list', items: ['条目', '条目'] }     // 清单型
```

写作建议：
- 每个 section 的 h 用"结论式标题"（如"为什么记录"而非"记录"）
- 优先用 list 表达要点，para 用于原理阐述
- 每篇必须给出"可执行建议"，避免纯理论
- 数字有依据：蛋白质 1.6-2.2g/kg、组间休息区间、有效组数 10-20 组等
- **合规红线**：不出现医疗用语（治疗/康复/诊断/治愈），用"建议/参考/有助于"替代；不承诺效果（"保证增肌"禁止）

## 3. 扩充内容流程（Checklist）

1. 新增动作 → 编辑部位文件 → `node test.js` 全绿 → 动作库页自动出现（无需改页面）
2. 新增部位 → 新建部位文件 + index.js 注册 MUSCLES/require → test 全绿 → 部位 chips 自动出现
3. 新增文章 → 编辑主题文件 → test 全绿 → 知识页自动出现
4. 每次内容改动后跑 `node test.js`（自动校验 id 唯一、字段完整、结构有效）
