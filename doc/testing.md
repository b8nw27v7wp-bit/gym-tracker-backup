# 测试文档（Testing）

版本：v2.1 | 更新：2026-08-11

## 1. 测试策略

- **数据层自动化**：计算/存储/内容完整性用 node 单测，`node test.js` 一键运行，85 项断言
- **页面层冒烟**：mock `Page`/`wx` 实跑页面交互逻辑（编辑/保存流程），见第 4 章
- **手工**：页面渲染与视觉在微信开发者工具中验证（见第 5 章）
- **回归**：任何数据层改动后必须 `node test.js` 全绿；页面逻辑改动后跑冒烟测试再提交

## 2. 自动化测试环境

test.js 通过 mock 全局 `wx` 对象（内存 Map 实现 get/setStorageSync），使 utils 层脱离小程序运行：

```js
global.wx = {
  _store: {},
  getStorageSync(key) { return this._store[key]; },
  setStorageSync(key, val) { this._store[key] = val; }
};
```

## 4. 页面冒烟测试（29 项）

mock `Page`/`wx` 环境实跑页面交互逻辑（BUG-003/004 回归 + 动作详情页关联知识）：

```js
// 关键 mock：Page 捕获配置 + setData 支持路径 key（'editing.sets[0].weight'）
global.Page = cfg => { pageCfg = cfg; };
global.wx = { getStorageSync, setStorageSync, showToast, showModal: o => o.success && o.success({confirm:true}), ... };
const page = Object.create(pageCfg);
page.setData = function (obj) { /* 路径解析后写入 this.data */ };
```

覆盖断言：

1. 添加动作进入编辑态，editing 为深拷贝（与 draft 解耦）
2. 重量/次数输入（路径更新）生效
3. 添加一组 / 删除一组（新数组引用）视图数据正确
4. 热身标记切换生效
5. 完成动作：编辑结果写回 draft、回选动作态、总容量计算正确
6. 保存：全空组过滤、全空动作（sets:[]）过滤、全空拦截不保存、有效动作数据完整、时长计算、保存后 draft 清空、删除动作

数据层 99 项 + 页面层 10 项（动作详情冒烟）= 109 项全绿为提交门槛。
