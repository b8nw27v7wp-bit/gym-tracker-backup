## 已关闭

### BUG-001 | 2026-08-11 | S4 | 已关闭
- 模块：训练页保存（方向一计划填充引入）
- 描述：计划填充的力竭动作（reps 留空）若用户直接保存，空组会存成 0 次，历史显示"0kg×0"
- 复现步骤：计划库 → 新手 C 日 → 开始训练 → 引体向上不填次数 → 直接保存
- 根因：保存逻辑未处理全空组（重量和次数都为空）
- 修复：保存时统计全空组，>0 时弹窗确认"自动跳过"，确认后过滤全空组再入库
- 验证：保存流程走查 + 45 项测试全绿

### BUG-002 | 2026-08-11 | S4 | 已关闭
- 模块：训练页搜索（方向二引入）
- 描述：输入纯空格时 searchKeyword 非空，页面显示空的"搜索结果"块而非部位选择
- 复现步骤：训练页 → 搜索框输入空格
- 根因：setData 使用未 trim 的原始输入
- 修复：onSearchInput 对输入 trim 后再 setData
- 验证：空格输入走查 + 49 项测试全绿

### BUG-003 | 2026-08-11 | S2 | 已关闭
- 模块：训练页组编辑（方向七后全量代码审查发现）
- 描述：编辑态所有操作（加组/删组/热身标记/重量次数输入/完成动作）均为"直接修改 this.data 引用对象后 setData 同一引用"。微信 setData 按 diff 推送视图，同一引用在 setData 前内容已变时 diff 检测不到变化，渲染层不刷新——表现为加一组无反应、输入数值后回列表不显示编辑结果（新基础库/真机上表现明显）
- 复现步骤：训练页 → 添加动作 → 点"＋ 添加一组"或输入重量 → 观察视图是否更新
- 根因：违反 setData 不可变更新约定（官方文档：直接修改 this.data 无法改变页面状态，会数据不一致）
- 修复：全部改为不可变更新——enterEdit 深拷贝编辑对象与 draft 解耦；加组/删组用 concat/slice 生成新数组；重量/次数/RPE/热身用路径更新 `editing.sets[i].xxx`；完成动作时深拷贝 draft 写回
- 验证：mock Page/wx 冒烟测试 19 项（编辑全流程/删除/保存结构）全绿 + `node test.js` 85 项全绿

### BUG-004 | 2026-08-11 | S3 | 已关闭
- 模块：训练页保存（方向七后全量代码审查发现）
- 描述：某动作的所有组全空时，保存只过滤空组但动作条目仍入库（sets: []），历史页显示"0 组"动作；若所有动作都空，仍会生成一条空训练记录
- 复现步骤：训练页 → 添加动作 → 不填任何组 → 直接保存
- 根因：doSave 仅过滤全空组，未过滤全空动作条目，也未拦截全空保存
- 修复：items 生成后 filter 掉 sets 长度为 0 的动作；所有动作都空时 toast 拦截不保存
- 验证：冒烟测试覆盖（全空动作被过滤、仅有效动作入库）

### BUG-005 | 2026-08-12 | S1 | 已关闭
- 模块：统计页部位分布（v2.2 文档核对时发现）
- 描述：stats.js 调用 `exercisesData.muscleName(k)` 取部位名，但 data/exercises/index.js 从未导出该函数，有训练数据时统计页部位分布渲染直接抛 TypeError 崩溃（白屏）
- 复现步骤：训练页保存任意记录 → 切到统计页（有数据）→ 崩
- 根因：index.js 导出了 muscleInfo 但无 muscleName；stats.js 按旧接口名调用，重构动作库时接口未同步
- 修复：index.js 导出 `muscleName: muscleInfo` 兼容别名
- 验证：`node test.js` 新增 muscleName 别名断言 + 统计页冒烟（157 项全绿）

### BUG-006 | 2026-08-12 | S1 | 已关闭
- 模块：全局（首次微信开发者工具运行发现）
- 描述：模拟器编译后所有页面整页白屏（tabBar 正常），Console 报 `module 'data/exercises.js' is not defined, require args is '../data/exercises'`
- 复现步骤：微信开发者工具导入项目 → 编译 → 所有 tab 页白屏
- 根因：微信小程序 require 不解析目录 index.js（与 Node 不同）——项目 11 个文件 12 处 `require('.../data/exercises')` / `require('.../data/knowledge')` 目录引用在微信环境全部失效；此前仅 node 测试通过（Node 支持目录解析），从未在微信环境运行过
- 修复：全部目录引用改为显式 `require('.../data/exercises/index')` / `require('.../data/knowledge/index')`
- 验证：`node test.js` 157 项全绿 + 模拟器编译通过 + 12 页面加载正常

## 审查清单（每轮改动）

1. 代码审查：数据层改动跑 `node test.js` 全绿
2. 边界审查：空输入/超长输入/重复点击/快速切换页面
3. 数据一致性：排序字段、周边界（周一）、时区
4. 兼容性：基础库 3.4.0+，iOS/Android 差异（输入框、键盘、safe-area）
5. 回归：改动影响面内的手工用例（doc/testing.md）
